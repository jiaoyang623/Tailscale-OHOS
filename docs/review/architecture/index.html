决策卡

每个决策选一个选项。要改就选「这个决策要改」，并写原因。

决策 1 · 停止连接的依据是什么？

原因：现有架构以状态判读驱动长时任务与恢复。状态缺失时会误判为用户停止。

决策 2 · 会话结束的原因由谁记录？

原因：两个进程都可能先退出。合并进诊断接缝会隐藏责任问题。

决策 3 · 恢复责任放在哪一层？

原因：扩展进程守着已建立的隧道。应用进程守着扩展进程本身。

决策 4 · 能量档位影响哪些部件？

原因：省电只能改变观测频率。隧道与恢复必须保持。
